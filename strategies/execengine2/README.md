# execengine2

Новый движок добавлен рядом со старым `execengine`. Он не меняет старые точки
запуска: переход можно делать по одной стратегии после тестов на реальном runner.

## Устройство

`Engine` — тонкий вход для событий. Изменяемые данные разделены между пятью
частями:

```text
Engine
├── quotes  — цены пары и их возраст
├── trade   — одна текущая парная сделка
├── orders  — наши заявки и защита от повторных fill
├── hedges  — проверка market-заявок и отложенные хеджи
└── run     — ready, fixing, check_needed или stopped
```

Части не читают поля друг друга. Они возвращают обычные значения, а `Engine`
вызывает `Broker`, `Strategy`, `SendLimit` и `Updates`.

Все методы `Engine` вызываются из одной горутины цикла событий. Внутри движка
нет мьютексов и фоновых горутин. Брокер и общий лимит сами отвечают за доступ из
нескольких горутин.

## Основной поток

1. `OnBook` сохраняет bid/ask и меняет цену открытой limit-заявки.
2. `OnSignal` получает `Plan` от стратегии и создаёт заявки новой сделки.
3. `OnFill` учитывает fill один раз. Первый fill снимает вторую limit-заявку и
   отправляет market-хедж.
4. `OnTick` проверяет таймауты, market-заявки и работу после ошибок брокера.
5. `CheckPositions` возвращает движок в `ready`, только когда позиции равны и
   не осталось заявок или хеджей в работе.

Режимы исполнения: `ModeTwoLimits`, `ModeLimitA`, `ModeLimitB` и `ModeMarket`.

## Лимит отправки

`budget.Atomic` хранит неизменяемый `reserve` и ровно одно изменяемое поле:
`atomic.Int64 remaining`.

- `Take` одной CAS-операцией проверяет и сразу списывает попытки;
- обычная заявка не может взять `reserve`;
- обязательный хедж может взять запас и увести остаток ниже нуля;
- `SetIfLower` принимает от брокера только меньшее значение;
- `Reset` вызывается снаружи; готовый `Controller` делает это по таймеру.

В лимите нет `time.Time`, mutex, пары `Allow`/`Spend` и возврата попытки после
ошибки. Попытка отправки уже могла дойти до брокера, поэтому она считается
потраченной.

## Ошибка отправки

Broker должен вернуть:

- `NotPlaced(err)`, если заявка точно не создана;
- `OrderUnknown(clientID, err)`, если заявка могла быть создана.

Во втором случае движок не создаёт новый ID и ждёт проверки позиций. Finam
реализация находится в `finambroker.Gateway`; она повторяет запрос только с тем
же client ID и останавливает ожидание через `ctx`.

## Подключение

```go
limit, _ := budget.New(100, 10)
broker, _ := finambroker.NewGateway(finamClient, limit, "[pair-a]")

engine, err := execengine2.NewEngine(execengine2.Config{
    LegA: "LEGA@RTSX",
    LegB: "LEGB@RTSX",
    Lots: 1,
    Mode: execengine2.ModeTwoLimits,
}, execengine2.Setup{
    Broker:   broker,
    Limit:    limit,
    Strategy: strategy,
})
```

Если лимит общий для нескольких движков, им передаётся один и тот же
`*budget.Atomic`.
